# ugBASIC refresh audit (2026-10-29)

## Verdict

ugBASIC `afd97a3` fixes both TMS9918 regressions found after `e35e6df`: 16x16 pattern conversion and
`SPRITE DISABLE`. The Warrior bitmap remains pixel-exact and the metasprite oracle now verifies the
exact pattern table, three active layers, priority colors and three safely hidden inactive layers.
The revision is therefore eligible for the ranked comparison.

## Source and optimizer audit

All six sources use `DEFINE DEFAULT TYPE BYTE`. Hello World and Controller Visual use `PRINT RAW`,
and the Warrior fixture uses `LOAD IMAGE ... EXACT COMPRESSED`, selecting ugBASIC's native MSC1
path. The empty demonstration loops identified by the ugBASIC author are not present.

| Maximum peephole passes | Six-sample total |
|---:|---:|
| 0 | 23,302 |
| 1 | 21,475 |
| 2 | 20,905 |
| 4, 8, 16, 32 or 64 | 20,905 |

The optimizer reaches its fixed point after two passes for this corpus. Raising the limit above the
default 16 cannot reduce any sample further. Evidence is generated by
`tools/audit-ugbasic-peephole-passes.ps1` under
`build/competition/ugbasic-afd97a3-peephole-audit/results.csv`.

The Warrior framebuffer remains pixel-exact despite 450 equivalent Pattern-byte and 1,322
equivalent Color-byte differences. ugBASIC now hides inactive sprites at `Y=192, X=255`; the oracle
accepts that valid offscreen representation as well as the earlier `255,255` representation. It
runs through initialization before checking both complete three-layer animation frames.

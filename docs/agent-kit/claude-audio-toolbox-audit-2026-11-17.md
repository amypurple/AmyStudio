# Claude audio toolbox audit - 2026-11-17

## Publication decision

`Polybius-B-v2.zip` is an experimental alternate production. It does not replace
the published `Polybius: The Tunnel` example, its project assets, ROM, screenshots,
or catalog entry. The B score is retained only as an audio-tool fixture because it
exercises a long four-voice arrangement.

## Adopted

- `tools/audio/os7music.py`: readable score to OS7 sound table, effects, size and
  duration report, PSG JSON and optional WAV preview.
- `tools/audio/os7check.py`: compares the score model against a PSG trace captured
  from the real OS7 BIOS.
- `tools/audio/psgsynth.py`: renders traced or modeled PSG states to WAV.
- Three bounded score fixtures: a compact three-tone march, the Gem Room tune and
  the experimental Polybius B title score.
- A discoverable Sound Workspace link that downloads the composer and the compact
  teaching score without modifying the open project.

The compact march was regenerated locally. Its result has six ordered table
entries beginning at `$702B`, four simultaneous music voices, two effects, 1,792
frames per loop and 3,616 encoded table bytes. The tone-3 31-frame rest regression
also passes by splitting `$FF` into `$FE,$E1`.

## Not adopted unchanged

- Claude's complete `SKILL.md` contains historical workarounds, including a Python
  play-once patch. Current Amy supports `play song Name once`; the local skill stays
  authoritative.
- `sfxkit.mjs` and `tunekit.py` overlap the Studio command editor and Tiny Sound
  sequencer. They remain useful evidence but are not a second canonical pipeline.
- `sound-table-layout.mjs` only checks the first area. Amy's existing validator also
  checks alignment, ordering, music/effect ownership and references, so it remains
  canonical.
- The generated four-voice format can cost more ROM than Tiny Sound. Agents must
  select it for audible need, compare encoded sizes, and avoid converting compact
  music merely because the richer tool is available.

## Next web step

The safe first web integration is discoverability and reproducible downloads. A
future in-browser score editor should reuse the same score corpus and compare its
generated bytes with `os7music.py` before it becomes authoritative. Porting only a
subset of the parser without byte-parity tests would create two incompatible music
formats and is rejected.
